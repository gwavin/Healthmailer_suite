printRxer / HealthMailer Suite Install Guide

Current release guidance | Windows x64 | IT and security review

Purpose

printRxer captures an approved clinical print job and creates a validated handoff package. HealthMailer watches the configured handoff folder and, when explicitly approved, sends the PDF through the logged-in user's Outlook/Healthmail profile. printRxer does not send email.

Deployment Roles

Machine RoleResponsibilitiesSetup Executable in Component Bundle
printRxer printing machinePrint/capture, recipient picker, PDF preparation, local outbox, validated handoff package creation.printRxerSetup.exe
HealthMailer sending machineHandoff watcher, validation, Outlook COM send, and terminal audit records. Chart/ViewPoint copy is removed/deferred.HealthMailerSetup.exe

Release Bundle

  • Build with tools/New-PrintRxerSuiteReleaseBundle.ps1.
  • The suite ZIP is the normal IT entry point and contains PrintRxerSuiteInstaller.exe.
  • Component ZIPs are provided for approved support or role-specific deployment.
  • Release ZIPs include SHA256SUMS.txt. Verify checksums before deployment.

Handoff Folder and Access Control

  • The same handoff path must be configured for both roles.
  • The handoff may be local for a same-machine pilot or a secured UNC path for split-machine deployment.
  • Use UNC paths directly rather than mapped drive letters.
  • IT owns share and NTFS ACLs. Restrict access to approved printRxer writers, the HealthMailer sender context, and approved administrators/support staff.

Installation

  • Smoke test first: run .\PrintRxerSuiteInstaller.exe --smoke-test from the extracted suite ZIP and stop if it fails.
  • Provision: use .\payload\setup\printRxerSetup.exe and .\payload\setup\HealthMailerSetup.exe with the same handoff path.
  • Validate: run both component setup executables with --validate after installation.
  • Run printRxer installation in an administrator-capable context because it installs the port monitor, PrintRxer XPS driver, printer queue, app files, and watcher task.
  • Run HealthMailer setup as the intended Outlook/Healthmail sender user so Outlook COM and the scheduled task use the correct Windows profile.
  • Live sending requires explicit installer-created approval. Use dry-run validation before enabling sending.
  • Validate the installation from the suite installer after setup.

Uninstall and Evidence

  • Standard uninstall preserves ProgramData, logs, configuration, archives, and audit/support evidence by default.
  • Use the remove-data option or --remove-data only for an explicitly approved clean lab reset.
  • Review support and audit requirements before deleting local data.

Security and Operational Checks

  • Keep release bundles and support bundles on approved HSE-controlled storage.
  • Support bundles exclude PDF payloads by default, but logs and metadata may still contain sensitive information.
  • Confirm the Outlook profile, recipient restrictions, handoff ACLs, scheduled tasks, printer components, and log rotation during deployment review.
