HealthMailer Outlook COM Troubleshooting

Current finding: HealthMailer is running and watching the correct handoff folder, but Outlook COM is failing before it can create the email.

Log Message Seen

Outlook COM method 'CreateItem' failed: The operation failed.
System.Runtime.InteropServices.COMException (0x80004005): The operation failed.

What This Usually Means

HealthMailer uses classic desktop Outlook COM automation. This error usually means Outlook is not available to the Windows user/session where HealthMailer is running, or Outlook has a prompt/profile issue preventing automated mail creation.

Most Likely Causes

  1. HealthMailer is running under the wrong Windows user/session.
    It must run as the same user who has the working Outlook/Healthmail profile.
  2. Classic Outlook is not available or not initialised.
    HealthMailer needs classic desktop Outlook. The new Outlook app does not provide the same COM automation.
  3. Outlook has a first-run or blocking prompt.
    Examples include profile selection, licence prompts, password prompts, mailbox setup, or add-in warnings.
  4. The task is running outside the intended interactive user session.
    Outlook COM is fragile when run outside the logged-in sender user's desktop session.
Important: Sign in as the intended Healthmail sender user before running these checks. Do not run the HealthMailer sending workflow as a different admin account unless that is the actual Outlook/Healthmail sender profile.

Step 1: Check the HealthMailer Scheduled Task

Open PowerShell as the intended sender user and run:

Get-ScheduledTask -TaskName HealthMailer |
  Select-Object TaskName, State |
  Format-List

(Get-ScheduledTask -TaskName HealthMailer).Principal |
  Format-List UserId, LogonType, RunLevel

Confirm that:

  • UserId is the intended Outlook/Healthmail sender user.
  • LogonType is appropriate for an interactive user session.
  • The task is present and not obviously disabled or broken.

Step 2: Validate HealthMailer

Run:

"C:\ProgramData\HealthMailer\app\HealthMailer.exe" --validate --config "C:\ProgramData\HealthMailer\healthmailer.settings.json"

This checks the installed HealthMailer configuration and Outlook registration. If validation fails, keep the output for support review.

Step 3: Manually Check Classic Outlook

  1. Sign in as the same Windows user shown in the scheduled task principal.
  2. Open classic desktop Outlook.
  3. Confirm the Healthmail account/profile is loaded.
  4. Create a new email manually.
  5. Resolve any prompts, licence messages, password prompts, or profile selection dialogs.
  6. Leave Outlook open.
  7. Print or process another test package.

Step 4: Check the Current Handoff Folder

The old log entries from 15 May used: 

C:\ProgramData\printrxer_v3\handoff

The current 28 May log entries show the corrected handoff folder: 

C:\ProgramData\printRxer\handoff

This suggests the current HealthMailer handoff path is corrected. The remaining issue is Outlook COM access.
